# Almanac v1 — Design

An offline sun & moon astronomy engine in Swift and TypeScript. Computes positions,
rise/set/twilight, moon phase and illumination, and lunar & solar eclipses — pure
functions, zero network, zero data files at runtime. Built for Slackwater (the
first consumer is [slackwater-ios#222](https://github.com/openwatersio/slackwater-ios/issues/222),
lunar eclipses in the tide timeline) but generic: nothing in the API knows about tides.

Algorithms are translated from [Astronomy Engine](https://github.com/cosinekitty/astronomy)
(Don Cross, MIT) and its sources — Montenbruck & Pfleger's *Astronomy on the Personal
Computer* for the lunar theory, truncated VSOP87 for the sun. Astronomy Engine is
unmaintained and ships no Swift target; its license permits translation with attribution
(see NOTICE).

## Why geometry-first

Position models come first; every feature above them is root-finding over the same
two models. An eclipse is found by searching the moon's distance from the real shadow
axis — not by a separate precomputed eclipse series (Meeus ch. 54) with its own error
budget. One error budget, and the eclipse answer is always consistent with the moon
position the caller draws.

## Scope

**In v1:** sun & moon geocentric/topocentric positions, ecliptic↔equatorial↔horizontal
transforms, refraction, ΔT, sun rise/set + civil/nautical/astronomical twilight,
moonrise/moonset, solar transit, moon phase events + illumination, lunar eclipse search
(type, magnitude, greatest-eclipse and contact times, local visibility), solar eclipse
search (global + local circumstances).

**Out of v1:** planets, transits of Mercury/Venus, libration, apparent magnitudes,
constellations, dates outside the ΔT polynomial range (~1600–2150), app integration
(adopting Almanac in slackwater-ios/-web is per-app follow-up work).

## Repo & packaging

`openwatersio/almanac`, public, MIT + NOTICE (Astronomy Engine, Montenbruck–Pfleger).

```
almanac/
  swift/        SwiftPM package, module Almanac
  typescript/   npm @openwatersio/almanac (ESM, zero dependencies)
  fixtures/     shared JSON test corpus + generate/ scripts (the parity contract)
  docs/
```

One version number spans both ports; every release is a `vX.Y.Z` tag. npm publishes
via OIDC trusted publishing; SwiftPM consumers pin the tag.

## Architecture — four layers, identical in both ports

- **L0 time** — Julian date, UTC↔TT, ΔT via the Espenak–Meeus piecewise polynomials.
- **L1 positions** — sun: truncated VSOP87 (earth); moon: Montenbruck–Pfleger MOON2
  (arcsecond-class, includes distance); nutation (truncated IAU 1980) and aberration.
- **L2 transforms** — ecliptic↔equatorial, equatorial→alt/az for an observer,
  atmospheric refraction, topocentric moon parallax (required for moonrise accuracy
  and local solar-eclipse circumstances — not optional).
- **L3 event searches** — root-finding over L1/L2: rise/set/twilights, moonrise/set,
  transit, phase events, eclipse searches.

## Public API

Pure functions, UTC instants in and out (callers localize), no shared state. Identical
names across ports:

`sunPosition`, `moonPosition`, `moonIllumination`, `sunEvents`, `moonEvents`,
`searchMoonPhase`, `nextLunarEclipse(after)`, `nextSolarEclipse(after)`,
`lunarEclipseVisibility(eclipse, lat, lon)`, `solarEclipseLocal(eclipse, lat, lon)`.

A drop-in superset of what `slackwater-ios` (`SunMoon.swift`) and `slackwater-web`
(suncalc) consume today.

## Fixture corpus — the parity mechanism

Twin hand-written ports stay identical through one shared corpus in `fixtures/`,
consumed by both test suites:

- **Positions** — sun/moon RA/dec/distance sampled across 1950–2100, sourced from the
  JPL Horizons API (authoritative — deliberately not generated from Astronomy Engine).
- **Events** — USNO rise/set/twilight times across a latitude grid including high-latitude
  edge cases; USNO moon-phase catalog.
- **Eclipses** — Espenak Five Millennium catalog subset (1900–2100): types,
  greatest-eclipse times, magnitudes; spot-checked local circumstances.
- **Parity file** — dense outputs generated by the TS port, asserted by the Swift suite
  at ~1e-9, catching port drift far below physical tolerances.

Tolerances are data, recorded in fixture metadata: sun ≤ 1′, moon ≤ 1′, event times
≤ 60 s, eclipse peak times ≤ 60 s. `fixtures/generate/` scripts are committed and
re-runnable; a `--check` mode fails on drift from the committed corpus.

## Testing & CI

TDD per layer; each layer lands fixtures-first. GitHub Actions: a node job (TS suite)
and a macOS job (`swift test`), both reading `fixtures/`. A release requires both suites
green against the same fixtures.

## Build order

TypeScript leads each layer (fixture tooling shares the language), Swift follows
immediately — the ports never sit more than one layer apart, so the parity file stays
honest end to end.
